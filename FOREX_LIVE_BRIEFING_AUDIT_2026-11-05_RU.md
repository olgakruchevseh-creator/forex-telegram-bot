# Forex · живой брифинг и аудит факторов направления

Дата: 05.11.2026. Исходник: предоставленный `forex-telegram-bot-main (2).zip`.

## Цель и реализованный объём

Во время торговой сессии сохранить исходный отправленный брифинг и после каждой НОВОЙ ЗАКРЫТОЙ общей H1 проверить, не устарел ли сценарий. При существенном изменении: отправить на русском отчёт «было → стало», обновлённый сессионный брифинг с семью парными карточками и пересчитанную объединённую картинку Echo + Next Pivot + ZigZag **только для изменившихся пар**. Пересмотр не равен торговому сигналу.

Реализовано в `live_briefing.py`, `bot.py`, `session_projection_reports.py` и флагах `config.py`.

- Контроль начинается только при наличии отправленного сессионного брифинга и валидного исходного снимка.
- Даже при задержанной доставке снимок M15/M5/H4/D1/W1 обрезается по фактическому закрытию общей H1; более поздние свечи не могут задним числом подтвердить прошлый H1.
- Базовые и очередные валютные баллы — из **одного** `briefing_strength_verified.calculate`: семь USD-мажоров Twelve Data, синхронная закрытая H1, лог-доходности 1/4/12/24 H1 (веса 15/35/30/20), шкала 0–100 — только отображаемый индекс, не вероятность и не будущая доходность.
- Направления берутся из существующего `briefing.build_pair_briefs` с его H1/M15/H4, структурой и H4 ZigZag. Снимок хранит H1/H4/D1, AMD, состояние и ZigZag H4; нет самостоятельной «новой стратегии».
- Уведомления при: смене подтверждённой стороны; утрате подтверждения; появлении нескольких новых подтверждений; смене приоритета; либо при развороте H1 как минимум у двух пар, даже если общий HTF ещё не подтвердил разворот. Последнее маркируется только как смена *контекста*.
- Дополнительные сообщения не отправляются при одной незначительной непроверенной перемене. На одинаковой H1 дубликаты не отправляются. Для некритического пересмотра действует 60-минутный минимум; подтверждённый разворот не подавляется этим интервалом.
- Сравнение с последним доставленным состоянием, история последних 24 важных изменений и ID последней проверенной H1 сохраняются в `state.json` (ключ `live_briefing`). При новом сессионном брифинге база начинается заново. Ранее отправленный брифинг не удаляется и не переписывается в Telegram.
- Если есть релиз экономического календаря HIGH/MEDIUM за последние два часа, он приводится лишь как событие **рядом по времени**. Доказанная причинно-следственная связь не утверждается. При отсутствии календаря неизвестная причина не подменяется вымышленной.
- Полный обновлённый брифинг содержит 7 парных компактных карточек; объединённая проекция пересоздаётся отдельной системой `session_projection_reports`, которая использует новую уникальную метку H1 и НЕ изменяет дедупликацию ранее отправленных сессионных Echo/Pivot карточек.
- Новая система **не** меняет Master Direction, торговые сигналы, сделки, TR, защиту новостей, дедупликацию существующих модулей или правило «только закрытая H1».

## Проверка того, кто/что влияет на направление (по исходному коду)

Это **разные масштабы**, а не идентичные независимые подтверждения. | **Высокий:** подписать конкретный метод на всех карточках, журналировать сравнение и проверить устойчивость решений на истории перед унификацией. ## Зачем не включены новые макрофильтры, блокирующие сигналы

Новости способны менять ожидаемую ставку и цену за секунды, но список новостей сам по себе не доказывает направление. Нельзя автоматически считать повышение CPI поводом для LONG USD, нельзя автоматически «перевернуть» Master при смене индекса 0–100. Добавление жёстких правил без причинной валидации могло бы вернуть проблему over-filtering и конфликтов модулей. Новая функция исключительно **информирует** и показывает подтверждённый сценарий по закрытой H1.

## Проверки

- `python -m compileall -q .` — успешно.
- `pytest` без четырёх старых тестовых файлов, импортирующих отсутствующий в данной проверочной среде пакет `python-telegram-bot`: **896 passed** (после финального прогона).
- Протестированы: одна закрытая H1 без изменений, утрата старого направления, полный разворот, конфликтный H1 без HTF, смена сессии, календарь только как контекст, отсечение более поздних M15/M5, недостоверная корзина, независимые ID и отсутствие повторной отправки картинок; отдельный дымовой тест `bot._maybe_send_live_briefing` с заменённым Telegram транспортом.
- Три исходных теста валютной силы исправлены для воспроизводимого времени: прежние проверки использовали текущую минуту, поэтому при запуске после 45-й минуты часа они ложно падали. Лимит боевого расчёта не изменён.
- **НЕ выполнены:** реальный Twelve Data/API, реальный Telegram/Railway, историческая проверка изменения win rate, демонстрация реакции на конкретную текущую политическую новость. Эти показатели нельзя гарантировать по статическим тестам.

## Внедрение

1. Сделать резервную копию текущего репозитория. Распаковать **маленький ZIP поверх корня Forex-репозитория**, сохранив структуру папок. Это не новый целый бот; заменяются только перечисленные файлы.
2. В Railway уже должны быть `TELEGRAM_TOKEN` и `TWELVE_DATA_API_KEY`. Для сохранения сравнения через рестарт нужен `STATE_DIR`, указывающий на **реально подключённый постоянный Railway Volume**; нельзя указывать несуществующую директорию и считать её долговременным хранилищем. На новых запусках активная сессия без нового исходного снимка не будет выдавать ложный пересмотр; первая база появится после очередного отправленного сессионного брифинга.
3. Настройки в `config.py`: `LIVE_BRIEFING_ENABLED`, `LIVE_BRIEFING_SEND_FULL`, `LIVE_BRIEFING_SEND_PROJECTIONS`, `LIVE_BRIEFING_MIN_REPORT_INTERVAL_MINUTES`. По умолчанию все сообщения включены; для уменьшения нагрузки можно отключить полный перепоказ или картинки, оставив краткий отчёт.
4. На неделе просмотреть в Railway `LIVE_BRIEFING_*` и убедиться в одном отчёте на H1 при значительном изменении, отсутствии дублей и совпадении меток H1. При отказе доставки картинок будет предупреждение, но старый сценарий не подменится.
5. Сначала наблюдать качество в дневных журналах; не считать подтверждённый сценарий автоматическим ордером.
