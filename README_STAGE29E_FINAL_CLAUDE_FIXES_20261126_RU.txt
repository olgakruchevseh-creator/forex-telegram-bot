ЧТО ПОПРАВЛЕНО

B1 · Шкалы качества
  - У Consolidation после бонуса за подтверждённый lifecycle теперь сохраняется
    единый потолок 95, как на исходной зоне (флаг в config.py).
  - Появилась команда владельца /quality_calibration. Она читает не более
    4 МБ из КОНЦА активного decision_journal.jsonl, не трогая архивы 27E.
    Выводит количество УНИКАЛЬНЫХ сценариев, медиану raw_quality,
    медиану итогового балла и долю событий, достигших потолка.
  - Бонусы остальных модулей НЕ перекалиброваны автоматически: для этого
    нужна фактическая выборка с завершёнными исходами и сравнение прибыли/
    отмены, а не синтетические числа. Это намеренно отложенная часть B1.

B2 · CRT: геометрия риска и первой цели
  - Когда риск/цель до СОБСТВЕННОЙ TR1 < CRT_MIN_RR_TO_TR1 (1.0),
    карточка помечается «КОНТЕКСТ · НЕ ТОРГОВЫЙ СИГНАЛ».
  - Точные цены подтверждения, SL, TR1, фактический штамп H1 сохраняются.
    Никакой искусственной дальней TR2 не создаётся.
  - Старое подтверждение CRT по прошлой H1 продолжает блокироваться
    event_not_current_h1, даже если R:R низкий и карточка информационная.
  - Успешная INFO-доставка получает module ACK; при смене формата старые
    ожидающие CRT-карточки мигрируют на новый hash ключ, не теряя состояние.
  - ВНИМАНИЕ: это осознанное изменение класса торговых CRT-сигналов.

C3 · Ненужная обработка устаревших pending
  - Следующая закрытая H1 удаляет недоставленную карточку подтверждённого
    H1-only события CRT, Liquidity Sweep, Daily High/Low, Disbalance,
    Consolidation. Применяется только к полноценной записи с event/setup ID.
  - Для M15/M5, неопределённых/legacy записей и других сканеров прежний
    MODULE_PENDING_MAX_H1=2 оставлен. Уровни и Silver Bullet не трогаем.
  - Release Guard по-прежнему отдельно запрещает поздние торговые входы.

C4 · Проверяемость времени события
  - Новый флаг STAGE29E_STRICT_EVENT_TIME=True запрещает торговую карточку,
    у которой отсутствует проверяемое время закрытия события.
  - Информационные карточки и ранний M15/M5 до своей H1 обслуживаются отдельно.
  - Старое значение STAGE27A_REQUIRE_EVENT_TIME=False не переписывается;
    новый флаг накладывает отдельную обратимую защиту.
  - После запуска смотреть в Railway Logs событие EVENT_TIME_MISSING_OBSERVE.
    При неожиданной массовой блокировке можно временно отключить
    STAGE29E_STRICT_EVENT_TIME и прислать логи, не меняя Master/Killer.
