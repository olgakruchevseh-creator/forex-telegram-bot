Дата: 20.11.2026

Файлы в этом маленьком ZIP (загрузить в корень GitHub):
1. ohlc_calendar_profiles.py — НОВЫЙ: обзор поставщика / торговых часов, расчет чувствительности ATR только для диагностики
2. ohlc_origin_report.py — ЗАМЕНИТЬ: краткая команда /ohlc_sources показывает оба календаря и конфликты по часам
3. patterns_history.py — ЗАМЕНИТЬ: пояснение к диагностике /patterns_history, какие свечи исключаются
4. test_ohlc_calendar_profiles_stage2z_20261120.py — НОВЫЙ: регрессионные тесты

Что подтверждено аудитом именно свежего проекта:
- В bot.py запросы интрадей Twelve Data уже содержат timezone=UTC.
- Свечи из ответа и RAM-кеша без календарного фильтра передаются в market[..]['H1'];
  следовательно потенциально доступны рабочим индикаторам. Влияние на каждый
  торговый сигнал или фактический ATR этим фактом еще НЕ доказано.
- /patterns_history уже применяет отдельный консервативный отбор H1 по обычным
  торговым часам Forex, исключает конфликтные цены, не заполняет пропуски.
- Действующая SQLite сохраняет сырые котировки из исторического ответа; запись
  first_seen после закрытия доказывает ретроспективную фиксацию, не историческую
  доступность цены боту в момент сигнала.

Что делает обновление:
- Короткая команда /ohlc_sources EUR/USD показывает отдельно выходные часы
  поставщика, консервативные часы Forex и чувствительность ATR(14) в двух
  просмотрах одного и того же кеша; без новых API вызовов.
- Разбивает расхождения archive vs cache по основным торговым/нерабочим/
  пограничным часам. Никакая версия спорной цены не выбирается автоматически.
- /patterns_history прямо объясняет разницу календарей; его консервативные
  ограничения на исторические проценты остаются на месте.

ОГРАНИЧЕНИЯ:
- Указание Twelve Data на Forex 24/7 / API v2 НЕ доказывает реальную
  возможность исполнения сделки через AvaTrade в выходной день.
- В документации поставщика timezone=UTC относится к внутридневным свечам.
  D1/W1 могут иметь иную часовую основу; метки не сдвигать автоматически.
- Точный календарь брокера, пересмотры свечей и первопричина 25 конфликтов
  не установлены. В пользовательском отчете «с движением» означает разницу
  OHLC внутри одной исторической свечи, а НЕ объем ликвидных сделок.
- Сравнение ATR — гипотетическая чувствительность по двум подвыборкам,
  не автоматический расчет реальных сигналов, и не исправление ATR торговли.
- Это OBSERVE_ONLY. Никаких изменений бот.py, Master, Killer, сигналов,
  порогов, внешних API запросов, SQLite и котировок.
- Многолетняя историческая дозагрузка НЕ включена (контроль лимитов API отдельно).

После установки:
1. Проверить GitHub Actions.
2. Убедиться в успешном деплое Railway.
3. В Telegram выполнить /ohlc_sources EUR/USD, затем /patterns_history EUR/USD.
4. Прислать короткий блок двух календарей и H1 конфликтов (весь список фигур не нужен).
