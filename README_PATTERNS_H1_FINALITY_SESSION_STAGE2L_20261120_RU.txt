ИЗМЕНЕНИЯ:
1) /ohlc_conflicts EUR/USD
   - Счётчик конфликтующих архивных H1 с first_seen раньше
     НЫНЕШНЕГО порога стабилизации 5 минут, после него, до закрытия
     и с неизвестным временем; показывает точные секунды (вместо
     округлённого «+0ч»).
   - Это НЕ доказывает, какая версия кода работала тогда, был ли
     повторный пересмотр API или использовала ли это торговля.
   - Все архивные значения SQLite и RAM-кеш сохраняются без изменений.
2) /patterns_formation EUR/USD D1
   - Для каждой фигуры отдельно: число основных H1, пограничных H1,
     закрытых для обычной FX-сессии часов, количество TF-меток в
     такие часы; «УСЛОВНО_ДА» вместо подтверждения D1/W1-сессии.
   - Данные D1/W1 Twelve Data могут быть привязаны к иной временной
     зоне; НИЧЕГО не сдвигается и не заменяется без верификации.
   - Отчёт /patterns_history предупреждает, что полное H1-покрытие
     D1/W1 не доказывает корректность границ D1/W1.
3) python h1_backfill_pilot.py --start-date 2026-11-02 --end-date 2026-11-04
   - ПО УМОЛЧАНИЮ ТОЛЬКО ПЛАН: 0 новых API-запросов, 0 записей.
   - Добавляет preflight_core_coverage_by_pair по всем семи парам:
     already_present_core / missing_core в запрошенном окне.
   - api_availability_verified=false; cost_verified=false.
   - Не менять STATE_DIR, Railway Service Start Command или переменные.
   - РУЧНОЕ выполнение с --execute --approve-api-requests существует
     в прежнем этапе 2К, НО сейчас его НЕ запускаем. Прежде проверяем
     лимиты Twelve Data и выбираем конкретное окно.

ВЫВОД АУДИТА ДО ОНЛАЙН-ПРОВЕРКИ:
- В свежем коде capture_market для H1 предусмотрены 5 минут
  стабилизации; он также проверяет, что источник запроса начался
  после закрытия H1. Эта текущая защита НЕ распространяется
  задним числом на старые записи SQLite.
- Из отчётов за 20.11 видно: 15.11 22:00 H1 впервые записана
  15.11 23:00:13 UTC (13 сек), 16.11 15:00 H1 записана
  16.11 16:00:32 UTC (32 сек). Это даёт основание отдельно
  изучить историческое поведение, но НЕ доказывает причину всех
  25 расхождений.
- Полное торговое покрытие интервала 07.11—09.11 (2 основных H1)
  не доказывает, что начало/закрытие дневных свечей соответствуют
  сессиям брокера; «2 D1 = 4 H1» остаётся условной метрикой.
- Для реального разбора 25 расхождений потребуется рабочая SQLite
  и отдельное разрешение на ручные точечные запросы поставщику.
