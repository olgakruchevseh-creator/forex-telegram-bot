ЧТО СДЕЛАНО

1) /disbalance_calibration [EUR/USD]  (команда существующая, отчёт теперь 28G)
   • Показываются отдельно завершённые исходы + исключённые события
     (INCOMPLETE_H1, OVERNIGHT_WINDOW, WEEKEND_H1_WINDOW,
     LATE_FIRST_OBSERVATION, INSUFFICIENT_PRIOR_H1, INSUFFICIENT_ATR).
   • Для первых исследовательских событий показываются пара, TF, время
     закрытия импульсного TF, время решения, задержка и балл качества.
   • Исследовательский replay удаляет из вычислительных снимков котировки
     выходного периода по существующему LIVE-фильтру (не удаляя их из SQLite).
   • Окна исходов ограничены 8 H1; нет будущих свечей во входном снимке.
   • TRAIN/TEST не смешиваются; результаты НЕ являются бэктестом фактически
     отправленных сделок и НЕ подтверждают статистическую вероятность.
   • Веса, пороги, формулы Disbalance, Master/Killer не изменены.

2) /w1_finality  (существующая команда, дополнительная диагностика 28G)
   • Чётко показана разница часов между NY Friday 17:00 и правилом +7 суток.
   • Проверяется факт появления последующей W1 и календарный интервал до неё.
   • Появление следующей метки доказывает НАЛИЧИЕ границы, но не отсутствие
     последующих коррекций цен W1 со стороны поставщика.
   • Фактическая торговая проверка закрытия W1 НЕ изменена.

3) /pdh_pdl_audit  (новая ручная команда)
   • Только из имеющегося кэша H1 и D1, без API-запросов.
   • Сравнение последнего завершённого NY-торгового дня (17:00 Нью-Йорк,
     с летним временем) с последним закрытым D1, без переписывания PDH/PDL.
   • В диагностике отдельно видны количество доступных H1, разрывы,
     исключённые Sat/Sun D1 и расхождения максимумов/минимумов.
   • Неполная H1-сессия отмечается PARTIAL_H1_SESSION; это не совпадение.

4) /storage_growth  (новая ручная команда)
   • При первом вызове сохраняется ТОЛЬКО маленький JSON-файл
     stage28g_storage_growth_observations.json внутри Volume.
   • При следующем вызове показываются изменения за интервал для активных
     и старых журналов decision/killer/unified, SQLite и прочих файлов.
   • Всего хранится не более 12 маленьких снимков (метаданные).
   • Старыe архивы 3.16 ГБ + 0.22 ГБ НИКАК не открываются по содержимому,
     НЕ удаляются, НЕ обрезаются и НЕ сжимаются. Внешние копии 27E по-прежнему
     НЕ подтверждены: не применять compact без подтверждения копии.
   • Изменение занятого места statvfs — показатель файловой системы, а не
     самостоятельное доказательство качества сигналов.

ГАРАНТИИ / ПРЕДЕЛЫ
  • OBSERVE_ONLY: сканирующие и торговые сигналы, ATR, Killer, Navigator,
    недельные свечи, выставление целей и логика PDH/PDL не тронуты.
  • Новые команды только для владельца: подключены через _owner_handler.
  • Нет новых запросов к Twelve Data.
  • Нет автоматической архивации или чистки при высоком заполнении Volume.
  • Перечень точных изменённых файлов проверен относительно данного ZIP.
  • Внутри ZIP нет .env, токенов, БД, SQLite, журналов или истории сделок.
