ЧТО СДЕЛАНО
- Отдельно аудируются текущий H1-кеш и архив SQLite: сколько свечей в
  каждом, сколько сомнительных выходных, сколько совпадающих H1-меток.
- Из существующей таблицы candles читаются (READ ONLY) source,
  first_seen_utc, last_seen_utc, если схема их содержит.
- Для конфликтов OHLC одной часовой метки показываются общее число,
  медианная и максимальная разница (пункты), до трёх примеров со временем
  и происхождением. Конфликт не устраняется произвольным выбором кеша.
- Исторический replay может использовать только независимо проверенный
  источник (или два проверенных источника вместе). Если один источник
  загрязнён выходными, он не используется. Спорные временные метки
  исключаются из ОБЕИХ версий; затронутые окна ATR/формирования/исхода
  отвергаются существующим контролем пропусков.
- Если оба источника имеют признаки нарушения целостности, исходы
  по H1 остаются полностью заблокированы. Нельзя обходить это правило.
- НИ ОДНА исходная свеча или строка SQLite не удаляется, не исправляется
  и не перезаписывается; запросы к Twelve Data дополнительно не делаются.
- Торговые сигналы, Killer, Navigator, M15/M5-подтверждения и пороги
  НЕ МЕНЯЮТСЯ; код задействован только по команде /patterns_history.

ВАЖНОЕ ОГРАНИЧЕНИЕ
Кодовый ZIP не содержит смонтированную на Railway базу SQLite.
По нему нельзя доказать, почему появились именно 88 свечей в выходные
и 25 конфликтов OHLC. После установки новая команда даст источники,
величины расхождений и примеры из имеющейся базы, но поле source
является МЕТКОЙ ПУТИ ПОЛУЧЕНИЯ, не независимым удостоверением котировок.
Историческая статистика не является гарантией будущего движения.

3. Дождаться GitHub Actions: полный тестовый прогон должен быть зелёным.
4. Убедиться, что в Railway развернулась именно эта версия.
5. В Telegram выполнить /patterns_history EUR/USD.
6. Прислать разделы: H1 контроль; H1 источники; H1 происхождение архива;
   H1 расхождения; H1 изоляция для replay. Также полезен журнал OHLC
