Также: /patterns_history GBPUSD. Для других пар аналогично.

РЕАЛИЗОВАНО:
- Только по явному запросу одной валютной пары, без минутного перерасчёта и без отправки торговых сигналов.
- Независимый проход по закрытым W1/D1/H4/H1/M15/M5.
- При распознавании каждой исторической фигуры используются только свечи, доступные на момент её подтверждения, без будущих данных.
- Раздельные исторические записи по TF, названию паттерна и направлению, защита от повторного подсчёта одного geometry_id.
- Если начало геометрии можно точно восстановить: число свечей формирования на своём TF и число РЕАЛЬНО ЗАКРЫТЫХ H1, попавших в период формирования.
- Отдельная оценка исхода по только полностью последующим закрытым H1: достигнута стандартная цель +1 ATR раньше стандартной отмены −0,75 ATR, отмена раньше цели, неопределённый порядок в одной H1, завершение по времени или недостаток наблюдения.
- Откаты по закрытиям H1 (порог 0,25 ATR), длительность до исхода, MFE/MAE в ATR.
- Честное n наблюдений, запрет процентного вывода при числе однозначно разрешённых исходов <10.
- Защита от некорректных/несинхронных OHLC и ограничение 64 историческими моментами на TF и 8 H1 на исход.
- Одновременную команду исторического анализа второй пользователь не запустит; расчёты выполняются вне основного цикла Telegram.

ОГРАНИЧЕНИЯ (ВАЖНО):
1. Это ПЕРВЫЙ рабочий слой исторической статистики, а не готовая вероятность успеха или доказанная прогнозная система.
2. Стандартная +1/-0,75 ATR — НЕТ реальные торговые TR1/TR2/TR3 и НЕ результат реального открытия сделки, спред/комиссия не учтены.
3. Если сигнал M15/M5 возник внутри H1, исход этой частичной H1 не анализируется по её high/low, потому что там есть движения ДО сигнала. Берутся только следующие ПОЛНЫЕ H1; это консервативно и может недоучитывать ранние срабатывания.
4. Для W1/D1 или долгой формации может не хватить загруженной истории H1; тогда «н/д» вместо придуманного количества часовых свечей. На Forex H1 сейчас ограничено количество свечей от провайдера.
5. Точную продолжительность формирования графических фигур без записанных опорных точек автоматически не придумываем — появится в следующем этапе после расширения идентификаторов геометрии.
6. В обычных сессионных брифингах и торговых карточках числа пока не добавляются: сначала проверьте корректность и потребление памяти команды на настоящих OHLC.
7. Не требуется изменение Railway Variables и не изменены правила финального решения по закрытой H1.
