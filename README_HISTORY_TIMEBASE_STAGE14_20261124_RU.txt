3. ЧТО НАЙДЕНО И ИСПРАВЛЕНО
A. Пустые выходные свечи в ATR (ИСПРАВЛЕНО).
   Twelve Data может отдавать свечи выходных без движения (O=H=L=C); в архиве
   есть такие записи. Они входили в ATR(14), EMA, ZigZag и счётчики баров.
   Моделирование: в понедельник 00:00 по Амстердаму ATR(14) H1 в 8–16 раз меньше
   реального, к 07:00 по Амстердаму — ещё на 40% ниже; все пороги в ATR
   (пробои, смещения, «далеко от уровня») становятся сверхчувствительными.
   Теперь живой поток выбрасывает ТОЛЬКО свечи без движения с открытием
   с пятницы 21:00 до воскресенья 22:00 UTC. Свечи с движением и все будние
   свечи остаются. Сырые свечи остаются в кэше и в SQLite-архиве.
   Побочный плюс: если у одной пары такие заглушки есть, а у другой нет,
   проверка синхронности корзины больше не глушит скан в понедельник.
   Откат одной строкой: config.LIVE_DROP_FLAT_WEEKEND_BARS = False.

B. Где на самом деле начинается D1 / W1 (ДОБАВЛЕНА ПРОВЕРКА).
   Документация Twelve Data: для 1day/1week параметр timezone игнорируется,
   метка — дата по времени биржи; для Forex зона по умолчанию Australia/Sydney.
   Бот считает D1 «2026-11-24» открытой в 00:00 UTC и закрытой в 00:00 UTC
   следующего дня. Если реальный день Сиднейский — бот лишь опаздывает
   (до ~11 ч видит вчерашний день как последний закрытый, PDH/PDL отстают).
   Если реальный день начинается ПОЗЖЕ 00:00 UTC — формирующаяся D1 считалась бы
   закрытой. По коду это установить нельзя, нужны реальные свечи.
   Новая команда /ohlc_timebase (без запросов к API, по кэшу) собирает каждую
   H4 и D1 из H1 той же пары (W1 — из проверенной H4) для каждого сдвига
   начала и показывает, какой сдвиг точно повторяет High/Low поставщика:
     «сдвиг +0» — разметка бота верна;
     «минус» — бот опаздывает (безопасно);
     «плюс» — риск: незакрытая свеча считается закрытой.
   Также показывает число выходных H1 (без движения / с движением) и D1 с
   меткой Сб/Вс. Раз в 6 ч то же пишется в лог Railway: OHLC_TIMEBASE_OBSERVE_ONLY.

4. ЧТО НАЙДЕНО И НЕ МЕНЯЛОСЬ (решение — после данных /ohlc_timebase)
- Воскресная D1: если поставщик даёт короткую воскресную D1, в понедельник
  PDH/PDL (daily_high_low, уровни W1/D1) берутся с неё, а не с пятницы.
  Исправлять вслепую нельзя: при Сиднейском дне свеча «Сб» — это пятничная
  сессия США. Нужна строка «D1 с меткой Сб/Вс» из /ohlc_timebase.
- Решения по закрытию H1 принимаются на первом ответе после закрытия, а журнал
  уже фиксировал правки Close поставщиком через 2–5 мин (OHLC_CLOSE_REVISION_*).
  Это компромисс «скорость / точность»; ожидание 2–3 мин — отдельное решение.
- Новости: по стороннему описанию бесплатный JSON Forex Factory не содержит
  фактических значений (actual). Тогда карточки «вышла цифра» и макро-реакция
  не срабатывают. Проверить здесь не удалось — смотрите, приходили ли такие
  карточки в Telegram.
- Журнал сигналов: пятничная запись после 20:00 UTC не набирает 8 непрерывных H1
  (выходные) и висит «в работе», пока не уйдёт из окна 250 H1.
- Weekly Rhythm: H4 воскресного открытия попадает в прошлую ISO-неделю.
- Мусорные файлы в корне: signal_context-1.py (старая копия, не импортируется),
  signal_context.zip, SMC_ROUTE_PATCH_115.zip (внутри СТАРЫЙ config.py) — лучше удалить.
- 11 ключей config читаются через getattr со значением по умолчанию (как на этапе 13).
