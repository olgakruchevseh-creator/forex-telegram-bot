ИЗМЕНЕНИЯ
1) /ohlc_sources EUR/USD: отдельный read-only разбор существующего файла
   $STATE_DIR/ohlc_close_revision_observe.json по совпадающим H1:
   - количество конфликтов со снимками наблюдателя;
   - только Close или другие поля OHLC;
   - API_RESPONSE против TTL/FALLBACK (только транспортная метка,
     НЕ независимое подтверждение цен Twelve Data);
   - более старые версии не смешиваются с текущим кешем.
   Если отчёта нет или он не соответствует конфликтам, это указано прямо.
   SQLite candles и revisions НЕ изменяются.
   ВАЖНО: revisions=0 в SQLite вполне возможно, поскольку автоматическое
   сохранение замораживает первые OHLC, а изменения позднее наблюдаются
   в отдельном JSON-файле — это не доказательство постоянства цены.

2) /patterns_history EUR/USD:
   - 0 H1 в короткой M5/M15 фигуре допустим, но пропущенный полный
     H1 на обычном торговом часу больше не превращается в 0;
   - исправлена проверка пропуска непосредственно перед подтверждением;
   - медиана H1 формирования берётся только по фигурам с полным покрытием;
   - выводится число фигур с полным H1 покрытием;
   - D1/W1 по-прежнему имеют неопределённую часовую основу,
     их H1 сопоставление является ПРЕДВАРИТЕЛЬНЫМ.

3) /ohlc_sources показывает ОДИН следующий 30-дневный интервал для
   потенциальной ручной H1-дозагрузки общей корзины из семи пар.
   Интервал считается ПО ВСЕМ парам, чтобы не рассинхронизировать историю.
   Это только план. Автоматических запросов и новых задач Railway нет.
   Тариф/остаток кредитов Twelve Data не проверялись, поэтому запускать
   массовую загрузку без проверки квоты не рекомендуется.
   Для ручного выполнения в проекте уже есть ohlc_history_journal.py fetch,
   но данный ZIP его НЕ запускает и НЕ изменяет.

ВАЖНОЕ ОГРАНИЧЕНИЕ
В ZIP нет живой базы SQLite с Railway и текущего RAM-кеша, поэтому
первопричина прошлых 25 расхождений не доказана и цены не исправлялись.
Автозапуск торговых сигналов, Killer, Master, правила закрытой H1, ATR
и торговые фильтры никак не менялись.
