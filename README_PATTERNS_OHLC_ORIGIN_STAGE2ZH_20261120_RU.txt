КРАТКАЯ ДИАГНОСТИКА ПРОИСХОЖДЕНИЯ OHLC H1 (OBSERVE_ONLY)

ФАЙЛЫ ДЛЯ GITHUB (поместить в КОРЕНЬ репозитория):
1) bot.py — ЗАМЕНИТЬ существующий файл.
2) ohlc_origin_report.py — ДОБАВИТЬ новый файл.

README-файл можно оставить у себя, на работу бота он не влияет.

Новая команда после успешных GitHub Actions и развёртывания Railway:
    /ohlc_sources EUR/USD
Можно использовать любую из семи поддерживаемых валютных пар.

Она выдаёт КОРОТКИЙ отчёт по источникам H1:
- размер SQLite-архива и покрытие W1/D1/H1;
- транспортные метки записей, отдельно от реальной исторической доступности;
- сколько свечей впервые были сохранены в течение часа после закрытия,
  через 1–24 ч, спустя >=24 ч или ещё до закрытия;
- количество H1 за закрытые часы Forex и время первого наблюдения;
- сравнение с УЖЕ ИМЕЮЩИМСЯ в памяти RAM-кешем (если он имеется);
- точные отличия OHLC архива и RAM-кеша на пересекающихся метках;
- число записей пересмотров в SQLite;
- последние результаты уже сохранённой проверки ohlc_vendor_probe.py
  (файл ohlc_vendor_probe_observe.json, если он уже есть).

Принципиальные ограничения:
- команда НЕ делает новые запросы к Twelve Data и НЕ расходует API-кредиты;
- SQLite открывается строго в режиме READ ONLY, исходные свечи НЕ изменяются;
- команда НЕ запускает загрузку истории, НЕ меняет ATR, Master, Killer,
  правила H1-close, фильтры сигналов или сессионные брифинги;
- отсутствие RAM-кеша после рестарта НЕ означает, что свечи исчезли из SQLite;
- время first_seen подтверждает лишь факт/время первой записи в SQLite;
  совпадение с текущим ответом Twelve Data НЕ доказывает доступность
  котировки в прошлом или независимую верификацию;
- длительная история W1/D1 требует отдельно спланированной H1-дозагрузки:
  учитывать тарифные лимиты/кредиты API и журнальные ревизии;
  АВТОМАТИЧЕСКУЮ пакетную дозагрузку этот этап намеренно НЕ включает.

Причина добавления команды:
По предыдущему отчёту H1 EUR/USD в архиве 88 выходных свечей; все
отмечены транспортной меткой BOT_SCAN_TWELVE_DATA_OR_CACHE. Первое
наблюдение H1 от 07.11 было лишь 15.11 — это похоже на ретроспективное
сохранение целой пачки. Причину выдачи самой свечи выяснить можно только
проверкой прямого поставщика, а не одним полем source.

ПРОВЕРКИ:
- локальные синтетические тесты для SQLite / RAM-кеша / даты first_seen,
  отсутствия API-запросов, read-only поведения, сохранённого vendor probe;
- полный CI на GitHub должен быть зелёным после загрузки файлов.

НАПРАВЛЕНИЕ ДАЛЬШЕ:
Перед исторической дозагрузкой нужны факты из /ohlc_sources EUR/USD
и подтверждение ограничений тарифного плана поставщика. Запрашивать
всю историю всех 7 пар каждую минуту НЕЛЬЗЯ.
