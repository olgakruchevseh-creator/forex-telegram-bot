# Личный FX-бот (мультитаймфрейм)

Бот смотрит 7 мажоров сразу на:

- неделя (W1)
- день (D1)
- 4 часа (H4)
- час (H1)
- 15 минут (M15)
- 5 минут (M5)

Сила валют считается по **закрытой H1** и только по полной синхронной корзине 7 пар.

## Как уходит сигнал

1. Брифинг — **от сессии к сессии** (Азия / Европа / Америка), не каждый час. Новости за час до события остаются отдельным потоком.
2. Модули работают по закрытым свечам и создают факты. Несколько фактов одной пары и стороны склеиваются в одно письмо.
3. В чат уходит только **ранняя точка**. Поздний вход не присылается.
4. За каждой направленной карточкой идёт Навигатор: маршрут TR1–TR3 и контроль отката по **часовым** свечам (глубина в % и оценка по времени). Откат не открывает противоположную сделку.
5. Картинки модулей сохраняются.
6. Неполная корзина котировок или массовый сбой сканеров — тишина в этот тик.

Команды: `/start`, `/now`, `/pair EUR/USD`, `/status`, `/briefing`.

## Запуск

```bash
cd forex-telegram-bot-main
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python bot.py
```

В Telegram: `/start`

Команды:

- `/now` — сила валют
- `/pair EUR/USD` — стек всех таймфреймов по паре
- `/status`
- `/briefing`

Платный Twelve Data: 7 пар на одном ТФ забираются одним batch-запросом.
Полный скан — 6 запросов ≈ 42 кредита. Проверка каждые `SCAN_EVERY_MINUTES` минут (сейчас 1).

## Подкрутить

| Что | Где |
|---|---|
| Мало сигналов | `MASTER_MIN_QUALITY`, `MAX_MODULE_ALERTS_PER_H1`. Сила и LTF сейчас штраф/контекст, не жёсткий запрет |
| Много карточек за час | `MAX_MODULE_ALERTS_PER_H1` |
| Неполная корзина | `MARKET_REQUIRE_COMPLETE`, `MARKET_REQUIRED_TFS` |
| Слишком строгий abort сканеров | `SCAN_FAIL_ABORT_RATIO` |
| Много шума с 5м | поднять `ZIGZAG_PCT["M5"]` |
| Кэш / частота | `ttl_min` у таймфрейма в `TIMEFRAMES` |

Правило старого стека: `decide_signal` в `analysis.py`.
Финальный торговый контроль: `master_direction.py`.
В чат: карточка модуля-источника + сопровождение `signal_navigator.py` (TR1–TR3), не два независимых входа.

## Railway: постоянное состояние

На Railway диск контейнера временный. После рестарта файлы рядом с кодом пропадают.

Нужно:

1. Подключить постоянный **Volume**.
2. Точка монтирования: `/data`.
3. Переменная: `STATE_DIR=/data`.

Тогда постоянно хранятся:

- `/data/state.json` — чат, брифинг, отправленные сигналы
- `/data/briefing.db` — атомарный замок сессионного брифинга
- `/data/levels_state.json` — уровни
- `/data/patterns_state.json` — паттерны
- `/data/poc_state.json` — антиспам POC между рестартами

Важно: путь `/data` без подключённого Volume **не** является постоянным хранилищем.

Обязательно для одного брифинга на одну сессию:

- Volume подключён, точка монтирования `/data`
- переменная `STATE_DIR=/data`
- **одна** реплика worker, не две и не три
- старые дублирующие сервисы того же бота выключены
- не запускать второй Railway-сервис с тем же Telegram-токеном
