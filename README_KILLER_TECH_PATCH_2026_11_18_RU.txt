ИЗМЕНЕНИЯ:
1. Hunter вызывается и при отсутствии допущенных сигналов других модулей.
   Самостоятельный поиск выполняется не чаще одного раза на новый закрытый H1,
   если нет новых допущенных карточек. Все созданные карточки продолжают
   проходить те же единые и финальные проверки перед отправкой в Telegram.
2. Для отказов по недостатку семейств добавлены shadow_partial_points,
   shadow_ltf и shadow_complete=False. Это неполная наблюдательная
   диагностика, НЕ торговый балл, НЕ процент вероятности и НЕ разрешение
   отправлять сделку. score=None для раннего отказа сохраняется.
3. У Killer появилась обязательная проверка времени закрытия H1/M15/M5:
   обе младшие серии должны содержать достаточно свежие закрытые свечи,
   а хотя бы один из M15/M5 должен подтверждать направление. При
   отсутствии/несвежести данных — отказ; торговля по незакрытой H1 не допускается.
4. Историческое воспроизведение изолирует живое состояние Baskerville,
   берёт сохранённые на момент решения H1 по SMT-парам, а для Setup Memory
   использует замороженный снимок либо пометку об отсутствии. При
   неполноте данных расхождение не объявляется доказанной ошибкой.
5. При недоступном новостном календаре Killer не публикует даже формально
   подходящие карточки; причина заносится в журнал (fail closed).

БЕЗ ИЗМЕНЕНИЙ:
  config.py и торговые пороги: KILLER_MIN_FAMILIES=5,

УСТАНОВКА С ТЕЛЕФОНА:
1. Скачайте архив и распакуйте.
2. В GitHub откройте свой репозиторий Forex -> Код.
3. Загрузите 5 файлов с расширением .py в КОРЕНЬ репозитория
   (НЕ в .github/workflows), заменяя 4 одноимённых файла; тестовый файл новый.
4. Подтвердите Commit changes.
5. Проверьте зелёные GitHub Actions, затем успешный Railway Deploy.
6. В Railway проверьте логи нового закрытия H1 и дневной журнал Killer.
   Рекомендуемые строки поиска: KILLER_REJECT, KILLER_ELIGIBLE,
   ltf_not_fresh, ltf_direction_unconfirmed, news_calendar_unavailable.

ВАЖНО:
Это реальные изменения маршрутизации и дополнительная защита LTF.
Количество кандидатов может вырасти, а число допущенных сигналов —
уменьшиться, если не было подтверждения M15/M5. После обновления
наблюдайте потребление памяти Railway и не оценивайте эффективность
по одному случаю 4/5. Отклонённые сделки не возобновляются автоматически.

Файлы состояния и журналы в ZIP не включены; токены и API-ключи не включены.
