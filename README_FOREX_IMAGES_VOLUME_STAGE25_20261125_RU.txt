УСТАНОВКА
1. Распакуй этот маленький ZIP.
2. Загрузи все перечисленные файлы в КОРЕНЬ репозитория GitHub одним коммитом,
   заменяя одноимённые. Никаких исходных файлов не удаляй.
3. Дождись GitHub Actions и активного Railway Deployment.
4. В Telegram боте отправь команду /storage и пришли ответ для анализа фактических
   размеров журналов, SQLite, WAL и файлов PNG.
5. Посмотри следующий сессионный брифинг. Если картинка для фигуры всё ещё
   не доставлена, ищи в Railway логах:
   PATTERN_BRIEFING_IMAGE_FAILED
   PATTERN_BRIEFING_IMAGE_SEND_FAILED
   PATTERN_BRIEFING_OBSERVED_FALLBACK_FAILED
   PATTERN_BRIEFING_NO_IMAGE

ИЗМЕНЕНИЯ
1. Показ наблюдательного изображения для M15/M5, когда на W1/D1/H4/H1 нет
   фигуры, но M15/M5 фигурирует в MTF-сводке. Обязательно OBSERVE_ONLY.
2. Иллюстрация должна соответствовать первой фигуре на старшем ненулевом
   таймфрейме из той же MTF-сводки; не показывать старую фигуру, когда на
   последних закрытых свечах нет подтверждённых фигур.
3. При уплотнении Telegram caption сохраняются предупреждения о том, что
   фигура младшего TF — НЕ подтверждение торгового сигнала или старшего TF.
4. Логи причин отсутствия изображения (без лишних файлов и PNG-записей).
5. Команда /storage (только чтение): ограниченный по времени сбор размеров
   файлов, список крупнейших файлов и approximate statvfs filesystem usage.
   Не читает содержимое JSONL/SQLite, не удаляет/не сжимает/не изменяет файлы.
   Команда доступна только чату, который уже сохранён как основной chat_id,
   если такой чат сохранён.

ВАЖНО
- ПРИ ОТСУТСТВИИ фигур на последних закрытых барах картинка не создаётся:
  это правильно, нельзя рисовать фиктивный паттерн.
- Одно изображение на пару в сессионном брифинге, остальные фигуры — текстом.
- Если Telegram отклонит send_photo, уже существующая функция бота отправит
  компактный текст, а причина будет в Railway логе.
- Эта версия НЕ очищает накопленные журналы и не освободит уже занятые 3.8 ГБ.
- Для безопасной ротации сначала нужен ответ /storage и план сохранения
  важных replay и OHLC файлов. SQLite и -wal вручную НЕ удалять.
- Master, Killer, ATS, расчёт целей и правило закрытой H1 НЕ ИЗМЕНЕНЫ.
