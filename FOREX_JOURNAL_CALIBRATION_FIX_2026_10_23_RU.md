# Forex Journal / Replay Calibration Fix — 2026-10-23

## Что исправлено

1. Decision Journal больше не записывает один и тот же факт одной закрытой H1 при каждом повторном скане как новое независимое наблюдение.
   - добавлен `scenario_id` для связи ALLOWED/BLOCKED/MASTER_CONFIRMED/SENT одного сценария;
   - `event_id` стал stage-specific;
   - в идентичность включена фактически наблюдавшаяся закрытая H1;
   - добавлена защита от повторной записи одинакового `event_id` в JSONL.

2. Replay теперь привязан к наблюдавшейся закрытой H1 (`observed_h1_dt`), а не к времени записи журнала через несколько минут.
   - первая H1 после решения больше не пропускается;
   - ATR для replay считается только по данным, доступным на момент решения, без будущих свечей;
   - добавлен fallback для старых schema=1 записей.

3. Daily Calibration считает статистику по уникальным решениям.
   - технические повторы показываются отдельно;
   - полезные/ошибочные блокировки больше не размножаются повторными сканами;
   - причины блокировок показываются шире, с `прочие N`, если список длинный;
   - entry timing показывается по всем SENT, даже если replay ещё не созрел;
   - отчёт остаётся строго OBSERVE_ONLY.

4. Signal Journal MFE/MAE исправлен.
   - MFE/MAE больше не продолжает расти после TARGET/INVALIDATED;
   - экскурсия замораживается на первом баре исхода или на 8H;
   - старые завышенные значения могут самовосстановиться при следующем `update_market`, если исходные H1 ещё доступны;
   - недельные MFE/MAE усредняются только по зрелым сценариям, открытые исключены.

5. Недельный отчёт теперь явно разделяет стандартизированный журнальный тест и реальные торговые TR.
   - `JOURNAL_TARGET_ATR` / `JOURNAL_INVALIDATION_ATR` — диагностический тест;
   - он не выдаётся за frozen TR1/invalidation торговой карточки.

## Что НЕ менялось

- `opposite_weaker` — торговый veto не ослаблен;
- `late_tr1` — порог не ослаблен;
- `pullback_strength_crush` — порог не ослаблен;
- Master Direction / Navigator / LONG-SHORT логика не менялась;
- режим Daily Calibration остаётся OBSERVE_ONLY.

Причина: до исправления телеметрии статистика блокировок была искажена повторными записями, поэтому менять торговые пороги по старому отчёту было бы статистически небезопасно.

## Проверка

- production/аналитический набор без Telegram-dependent suites: `780 passed`;
- четыре Telegram/import-dependent integration suites сравнены с исходным ZIP: 11 старых failures воспроизводятся и в исходной базе; текущая доработка новых failures в них не добавила.
