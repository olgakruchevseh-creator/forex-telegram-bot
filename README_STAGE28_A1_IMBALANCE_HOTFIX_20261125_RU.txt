Дата: 25.11.2026
База: действующий проект с этапами 27A—27E.

ЗАЧЕМ
В stage27a_event_integrity.prune() ошибочно предполагалось,
что item['event'] всегда dict. Реальный Imbalance сохраняет event
строкой: 'new', 'retest', 'ifvg_retest'. При повторном сканировании
это вызывало AttributeError и прерывало обработку Imbalance.

ИСПРАВЛЕНО
- Строковые event и другие несловарные поля zone безопасно обрабатываются.
- Одна повреждённая запись pending теперь не останавливает весь сканер;
  удаление повреждённого элемента фиксируется в логе с reason=corrupt.
- Существующие правила H1-close, TTL, фильтры и параметры не менялись.
- Нет массовой очистки state / журналов и нет операций с Railway Volume.

1. stage27a_event_integrity.py  (заменить существующий)
