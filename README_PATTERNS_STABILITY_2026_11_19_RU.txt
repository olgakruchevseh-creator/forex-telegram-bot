Это НЕ новая версия исторической математики паттернов или расширения MTF.

ЧТО ИСПРАВЛЕНО
- Просроченные события больше не возвращаются на отправку бесконечно.
- При истечении срока удаляется сохранённое PNG соответствующей очереди.
- Старые события отмечаются как использованные, чтобы не возникали новые
  повторные PENDING для одной и той же фигуры.
- Для диагностики дополнительно ведётся ограниченный журнал expired
  с причинами expired_pending / event_too_old_for_new_alert.
- Повторное сканирование НЕИЗМЕНИВШИХСЯ закрытых свечей использует кеш
  результата обнаружения, без повторного расчёта геометрии.
- Любое изменение OHLC уже закрытой свечи сбрасывает кеш; незакрытые
  свечи не участвуют в ключе кеширования.
- Кеш содержит только ключи/итоги анализа и ограничен 8 парами,
  не хранит исходные массивы рыночных свечей.
- Лог PATTERNS_CYCLE показывает duration_ms, analysis_reused,
  analysis_fresh, pending_expired, old_events_skipped,
  pending_active, cards_in_memory.

СОВМЕСТИМОСТЬ
При первом запуске старые PENDING без created_at проверяются по
исходному времени закрытия паттерна. Некорректные/просроченные записи
удаляются безопасно. Новые паттерны создают created_at и сохраняются до
подтверждённой доставки, но не дольше актуального окна.

Локально: 31 целевой тест успешно пройден.
Широкий запуск со смежными модулями не завершился в ограниченное время.
ПОЛНЫЙ набор тестов подтвердить через GitHub Actions после установки.

УСТАНОВКА
1. Сохранить текущую рабочую версию GitHub (предыдущее состояние).
2. Распаковать ZIP и загрузить ТРИ .py файла в КОРЕНЬ Forex репозитория.
3. Подтвердить замену patterns.py и config.py и добавление теста.
4. Дождаться зелёного статуса GitHub Actions, проверить число тестов.
5. Проверить статус Railway / worker / Deployments.
6. В логах Railway найти PATTERNS_CYCLE и сравнить duration_ms,
   analysis_reused и pending_active несколько циклов подряд.
7. Сравнить Memory после одинакового интервала БЕЗ перезапусков.
