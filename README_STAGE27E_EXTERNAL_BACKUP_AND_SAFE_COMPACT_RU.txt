ВАЖНО СРАЗУ
------------
Установка 27E НЕ УДАЛЯЕТ ФАЙЛЫ и НЕ ОСВОБОЖДАЕТ МЕСТО автоматически.
У вас сейчас примерно 77.4% заполнения, ~1 ГБ свободно. Патч создаёт
безопасную ПОСЛЕДОВАТЕЛЬНОСТЬ ДЕЙСТВИЙ. Для удаляемой несжатой части
потребуется реально доступная ВНЕШНЯЯ копия, подтверждённая по SHA-256.

Если внешнего хранилища нет, НЕ запускайте команду compact — она в любом
случае будет заблокирована. Railway Backup полезен для аварийного
восстановления, но не заменяет постоянную независимую копию вне Railway.

ОБЩИЙ ПРОЦЕСС
--------------
1. После загрузки ZIP GitHub Actions и Railway должны быть зелёными.
2. В Telegram: /storage_archive status — лишь посмотреть состояние.
3. Настроить ЧАСТНЫЙ бакет с поддержкой больших объектов и двух временных
   ПОДПИСАННЫХ HTTPS URL для ОДНОГО и ТОГО ЖЕ удалённого объекта:
     - HTTPS PUT (отправить необработанный JSONL)
     - HTTPS GET (полностью прочитать обратно и сверить SHA-256).
   Сервис хранения может быть S3-совместимым. Он должен поддерживать
   однократный PUT для фактического размера файла (~3.2 ГБ).
   Если URL подписан с ограничением Content-Type, использовать
   application/octet-stream. Срок действия URL должен покрывать ПОЛНОЕ
   время загрузки И повторного чтения — это могут быть длительные операции.
   Удалённый объект должен оставаться в вашем частном хранилище после
   истечения срока действия ссылки (без автоочистки по короткому TTL).

4. В Railway → сервис worker → Variables, добавить ЧЕТЫРЕ переменные
   (можно сначала только две для самого большого журнала):

   STAGE27E_DECISION_PUT_URL = <подписанный HTTPS PUT для decision>
   STAGE27E_DECISION_GET_URL = <подписанный HTTPS GET для ТОГО ЖЕ объекта>

   STAGE27E_KILLER_PUT_URL   = <подписанный HTTPS PUT для killer>
   STAGE27E_KILLER_GET_URL   = <подписанный HTTPS GET для ТОГО ЖЕ объекта>

   НЕ присылайте эти ссылки или секреты в Telegram/чат и не записывайте их
   в config.py/GitHub. Задавать только как СЕКРЕТНЫЕ Railway Variables.
   Разным журналам нужны РАЗНЫЕ внешние объекты.

5. Для большого журнала решений отправить владельческую команду:

      /storage_archive export decision CONFIRM

   Worker потоково считает SHA-256 оригинала, делает HTTPS PUT, затем
   полностью скачивает содержимое обратно по HTTPS GET в памяти небольшими
   порциями и сверяет ТОЧНОЕ совпадение размера и SHA-256. На Volume не
   появляется вторая копия 3.2 ГБ! В логах ссылки не раскрываются.
   До финального сообщения «Внешняя копия проверена» НИЧЕГО не сжимайте.

6. Только после УСПЕШНОЙ проверки, отдельной командой:

      /storage_archive compact decision CONFIRM

   Программа повторно проверит локальный SHA-256 против полученного ранее
   внешнего, свободный резерв на Volume (минимум 300 МБ), создаст временный
   gzip с ограничением размера, полностью распакует его для повторной
   проверки байт/контрольной суммы и только после этого удалит НЕСЖАТЫЙ
   архивный оригинал. Сжатый gzip остаётся на Volume и доступен журналам,
   а независимый оригинал остаётся в вашем внешнем облачном хранилище.
   Если экономии места нет, операция отменяется без удаления оригинала.

7. В Telegram отправить /storage и /storage_archive status. Проверить
   фактическое свободное место, новый *.jsonl.gz и отсутствие старой
   несжатой копии. При необходимости провести два шага с killer:

      /storage_archive export killer CONFIRM
      /storage_archive compact killer CONFIRM

   Их выполнять раздельно и только после сообщения об успехе.

КОМАНДЫ
-------
/storage_archive status                  просмотр, не меняет файлы
/storage_archive export decision CONFIRM внешний перенос и ПОЛНАЯ проверка
/storage_archive compact decision CONFIRM безопасное проверенное сжатие
/storage_archive export killer CONFIRM   аналогично для Killer
/storage_archive compact killer CONFIRM  аналогично для Killer

Все команды доступны лишь основному чату владельца, который защищён
27A. Возможна только ОДНА операция в worker, повтор отклоняется. Сами
файлы и пути выбираются по строгому списку, никаких пользовательских путей.

ЧТО ПРОИСХОДИТ ПРИ СБОЕ
-----------------------
- Неверный HTTPS URL, 403/500, разрыв соединения, несовпадение удалённого
  SHA-256: проверка не создаётся; оригинал не удаляется.
- Изменился оригинальный сегмент, недоступен резерв диска, gzip повреждён:
  несжатый оригинал не удаляется.
- Падение процесса после создания проверенного gzip, но до удаления raw:
  обе копии остаются, следующая ручная команда повторно проверяет обе.
- Падение после удаления raw: в момент удаления уже существуют независимая
  подтверждённая внешняя копия и локальный проверенный gzip.
- Команды не выполняются автоматически при запуске; сканеры и H1 торговые
  правила не меняются.

ОПТИМИЗАЦИЯ ЧТЕНИЯ
-----------------
Для огромного архива создаётся маленький проверяемый кеш последних до
20 000 полных строк (не более 96 МБ). Чтение коротких tail-отчётов использует
кеш; если запрошено больше данных, остаётся стандартное чтение полного gzip.
Кеш не является источником истории: при неверном SHA-256 или отсутствии
кеша используется исходный gzip. Исходные исторические записи не меняются.

ОГРАНИЧЕНИЯ
-----------
- Из Cloud/Railway нельзя автоматически получить внешний бакет. Его нужно
  предварительно создать/подключить и дать подписанные URL в Variables.
- Пакет не обеспечивает бессрочное хранение внешней копии: срок хранения
  настраивается владельцем бакета. Проверяйте это отдельно.
- PUT+GET полного 3.2-ГБ объекта требует значительного трафика и времени;
  расходы зависят от выбранного облачного сервиса.
- Во время длительной операции не перезапускайте worker и не меняйте URL.
  Если нужно, выберите время вне наиболее важных торговых сессий.
- Если Volume почти заполнен или нельзя создать частный бакет, разумно
  временно увеличить объём диска Railway. Не нажимайте Wipe Volume.
- 27E не удаляет 15 старых ротаций unified_signal_decisions: приоритетом
  является 3.2-ГБ основной журнал; другие ротации отдельно аудируются.
- Проверку всего набора тестов с Telegram SDK выполнит GitHub Actions.

ФЛАГИ В config.py
-----------------
STAGE27E_ENABLE_MANUAL_OPERATIONS=True — разрешает только явные команды.
STAGE27E_MIN_FREE_RESERVE_BYTES=300000000 — минимальный резерв диска.
Чтобы заблокировать export/compact: выставить
STAGE27E_ENABLE_MANUAL_OPERATIONS=False. Старые gzip останутся читаемыми.
