FOREX PATTERNS 2.0 — ЭТАП 2Е
===================================
Цель: не терять всю историю H1 из-за закрытых часов Forex внутри исходного
набора, но не использовать их и спорные OHLC для расчета исходов паттернов.

СОСТАВ (файлы кладутся в КОРЕНЬ репозитория GitHub):
1) patterns_history.py — ЗАМЕНИТЬ.
2) patterns_history_sources.py — ЗАМЕНИТЬ.
3) test_patterns_history_sources_stage2d_20261120.py — ЗАМЕНИТЬ
   (обновлены проверки старого строгого поведения под новый безопасный отбор).
4) test_patterns_history_segments_stage2e_20261120.py — ДОБАВИТЬ.
Этот README можно оставить отдельно или загрузить по желанию.

Что изменилось:
- При наличии только выходных аномалий источники не отбрасываются целиком:
  для ретроспективного OBSERVE_ONLY создается временный список структурно
  допустимых H1 (без записи обратно в SQLite).
- Все заведомо закрытые часы Forex исключаются. Подозрительные H1 не смещаются,
  не интерполируются и не заменяются искусственными свечами.
- Каждая несовпадающая OHLC-метка целиком исключается из обоих источников,
  даже если расхождение мало. Нельзя молча выбирать «верную» версию.
- Если источник имеет дубликаты, неверное время, внекратную часу метку,
  перепутанный порядок, поврежденный OHLC или незакрытый H1, он полностью
  отвергается (не очищается автоматически). Другой источник обрабатывается
  отдельно. Если пригодных H1 нет — остается отказ.
- Пробелы в торговых часах после изоляции остаются реальными пробелами;
  существующие проверки ATR, формирования и горизонта исходов отвергают
  затронутые наблюдения. Обычные выходные промежутки не заполняются.
- Отчет показывает число подозрительных выходных свечей по сохраненным
  транспортным меткам SQLite и по одной временной метке/first_seen для
  каждого типа транспорта (до 3 примеров). Это НЕ доказательство API-поставки.
- Для источников с выходными аномалиями или конфликтами результат строго
  ПРЕДВАРИТЕЛЬНЫЙ. Успешность в процентах из таких данных не публикуется
  даже при наличии >= 10 однозначных наблюдений.
- Код торговых сигналов, Master, Killer, пороги H1 и поставщик данных
  НЕ менялись. Запросов Twelve Data патч НЕ добавляет.
- НИКАКИХ удалений, миграций или изменений SQLite не выполняется.

Проверка локально:
  python -m pytest -q test_patterns*.py test_ohlc*.py
Результат здесь: 138 пройдено, 2 пропущено.
Полный локальный набор НЕ проверен из-за отсутствия библиотеки telegram,
поэтому проверьте GitHub Actions на установленном окружении.

После зеленого GitHub Actions и успешного Railway Deploy:
  /patterns_history EUR/USD

Сначала посмотрите: H1 источники; H1 выходные в SQLite по транспортной метке;
H1 расхождения OHLC; H1 изоляция для replay; H1 разрывы в отобранном наборе.
Ожидаемое число H1 зависит от фактической базы и нового момента запроса.

ОГРАНИЧЕНИЯ / НЕ ВЫДАВАТЬ ЗА ДОКАЗАННОЕ:
- В архиве пользователя известны 88 выходных H1 и 25 конфликтов, но сам
  файл Railway SQLite не входил в ZIP. Конкретное происхождение этих свечей
  пока НЕ доказано.
- Состояние графиков рынка и котировки по выходным могут иметь особенности
  у отдельных провайдеров. Здесь используется консервативная контрольная
  сетка основных торговых часов Forex, а не независимый аудит vendor API.
- Доля целевых исходов, рассчитанная только по структурно допустимым H1,
  остается ретроспективным наблюдением и не является подтвержденной
  торговой вероятностью или реальными TR1/TR2/TR3.
