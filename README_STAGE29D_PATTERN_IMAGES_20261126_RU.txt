ВАЖНЫЕ ВЫВОДЫ АУДИТА
1. Все 10 исходных Python-файлов пакета 29C сравнивались побайтово со свежим полным ZIP: совпали.
   Настройки 29A/29B, новые тесты 29A/B/C присутствуют. AST: 497 исходных Python-файлов без ошибок.
2. В ПАТТЕРНАХ БРИФИНГА: briefing_htf_card() по контракту возвращает None, когда последняя
   закрытая свеча не даёт подтверждённой фигуры. Бот тогда отправляет текст без картинки.
   Это одна из доказанных причин отсутствия фото (не обязательно именно в наблюдавшемся USD/JPY).
3. В ТОРГОВЫХ КАРТОЧКАХ: источник паттерна проверялся по видимому тексту первичной карточки,
   но он может быть заменён общим контекстом. Теперь проверка по ORIGINAL source_text
   предшествует чужим заголовкам (например, IMBALANCE), картинка достаётся по source_text.
4. Если повторный рендер сохранённого сигнала из оперативного кэша не удался, раньше
   картинка из уже записанного PNG на Volume не пробовалась. Теперь используется файл
   event-time PNG (если он существует и доступен). Исходную историю не изменяем.
5. Телеграм измеряет длину подписи к фото в UTF-16, а не Python len(); emoji занимают
   два code units. Для торговых картинок используется безопасная проверка UTF-16.
6. Причину отсутствия картинки после деплоя нельзя установить без Telegram/Railway логов.
   Добавлен защищённый командой владельца диагностический отчёт, чтобы в следующий раз
   отделить отсутствие подтверждённой фигуры от ошибки Pillow и ошибки Telegram.

  * итог отправки каждой пары логируется и доступен через /pattern_image_status;

  * photo captions рассчитываются по UTF-16, поток фотографии возвращается к началу;
  * успешную/неуспешную отправку картинки различаем, на NetworkTimeout не делаем
    слепого повторного send_photo из-за риска дублирования.

- test_stage29d_pattern_briefing_images_20261126.py: новые регрессионные сценарии.

НОВОЕ В TELEGRAM
После ближайшего БРИФИНГА запустить:
/pattern_image_status

Статусы:
PHOTO_SENT PATTERN — полноценная картинка фигуры отправлена Telegram API;
PHOTO_SENT OHLC — отправлен честный обзор OHLC (паттерна нет либо рендер недоступен);
TEXT_ONLY ... — фото не построено, отправлен текст;
SEND_FAILED TelegramError — Telegram API отклонил фото, отправлен текст;
RENDER_ERROR — сбой оригинального графика, до попытки OHLC fallback.
Команда отражает ПОСЛЕДНИЙ брифинг в памяти процесса; после рестарта счётчик пуст.
Одна отправка Telegram API не доказывает визуальное отображение в приложении пользователя.
Если ещё раз исчезнет фото по USD/JPY — прислать /pattern_image_status и время сообщения.
В Railway поиск: PATTERN_BRIEFING_IMAGE_STATUS, PATTERN_BRIEFING_IMAGE_FAILED,
PATTERN_BRIEFING_IMAGE_SEND_FAILED, PATTERN_ALERT_IMAGE_UNAVAILABLE.

ФЛАГИ ОТКАТА (config.py):
STAGE29D_BRIEFING_OHLC_FALLBACK = True
STAGE29D_BRIEFING_IMAGE_DIAGNOSTICS = True
Поставить False и снова деплоить при проблемах с CPU/памятью. Ранее существовавший
PATTERN_CHART_IMAGES_ENABLED=False отключает все эти картинки целиком.
